# 0.3 通用性审查

定位是单人自托管、多设备、多受众的状态服务。核心协议不依赖 QQ、Poweramp、博客域名或特定用户；设备身份由写入凭据决定，读者只得到被授权的设备与字段。个人部署绑定保存在忽略的私有配置中。

| 层次 | 可复用能力 | 当前边界 |
| --- | --- | --- |
| 服务端 | 标准 HTTP/JSON、独立凭据、应用/播放器白名单、受众投影、TTL | 单主人实例；没有账户注册、多用户隔离后台、凭据管理 UI |
| Android | 标准 MediaSession、UsageStats、SAF，免 Root | 播放器必须正确暴露元数据；只实机验证一台 Android 16 手机与 Poweramp，不能宣称所有 ROM 兼容 |
| 歌词 | 通用 MP3 USLT/SYLT、FLAC Vorbis、M4A 标签和 LRC | 严格元数据匹配；原始 AAC、特殊标签、纯文本同步不支持；同名重复文件拒绝猜测 |
| Windows | 前台进程白名单、锁屏和空闲隐藏 | WPF/.NET 8；无 Linux/macOS、系统托盘、自启动和 Windows 音乐采集 |
| 网页 | 消费公开或授权的原生 API，歌词窗口内存缓存 | 轮询校准；没有推送通道；不提供历史活动存储 |
| AstrBot | 独立插件按消息事件和群权限调用 API | 当前为 QQ/OneBot aiocqhttp + 中文规则，单设备主人；其他平台需实现身份适配 |

## 机器人如何判断角色

`integrations/astrbot/main.py` 是自写插件，`identity.py` 是保守的目标解析器。

1. 当前平台、群号、发送者、真实 @ 来自 AstrBot 消息事件，不接受模型传入的人物 ID。
2. “我”取真实发送者；明确 @ 或 QQ 号取该成员；“设备主人”及配置别名取私有绑定。
3. “群主”通过 OneBot `get_group_member_list(no_cache=True)` 获取唯一 `role=owner` 成员；接口失败不返回状态。
4. 目标必须等于该群配置的设备主人，才使用该群只读令牌访问 State of Me。未绑定、歧义、群主已转让均不会回退到主人的状态。
5. 当前请求会注入设备主人和发言者身份提示，帮助模型正确归属工具结果。这不是全局记忆；真正的数据访问限制在插件代码和服务端凭据。

现有中文规则不是完整自然语言指代解析：“他呢”需要追问；正文中的长数字可能被当成 QQ 号。工具名 `get_my_status` 为兼容现有设置保留，但语义是查询消息明确指定的人。未来多用户能力需要显式用户与设备绑定模型，不能仅放宽目标检查。

本次结论：适合其他人复制配置并独立部署；不能称为全平台、多租户成熟产品。下一优先级是标准化身份适配接口、设备配对与凭据管理，以及扩大真机兼容验证。
