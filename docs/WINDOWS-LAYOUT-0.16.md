# Windows 四页布局（0.16）

Windows 使用 WPF UI 的 NavigationView、FluentWindow、TitleBar 和按钮，主窗口固定为概览、采集、分享、设置四个入口。账号管理嵌入主窗口，没有综合账号弹窗。

| 页面 | 信息与操作 | 保存边界 |
| --- | --- | --- |
| 概览 | 当前应用与媒体、同步计数、WhatPulse 已采集统计、临时状态、诊断 | 临时状态单独保存；开始／暂停同步单独操作 |
| 采集 | 应用模式与名称名单、播放器与歌词目录、设备与系统信息、WhatPulse 开关／端口／连接诊断 | 保存本机采集设置，保留原有运行或暂停意图 |
| 分享 | 公开展示、QQ 群两个二级页；群验证和字段选择在同处完成 | 各受众分别保存，沿用服务端字段目录和版本冲突保护 |
| 设置 | 服务地址、账号登录／注册／恢复、设备管理、本机断开、启动项 | 账号动作、设备动作和开机启动分别操作 |

用词区分：采集信息上传到自己的账号称为“同步”，允许访客或某个群读取称为“分享”。新设备仍默认暂停，登录登记成功不自动开始同步。概览的开始按钮使用已保存的采集设置；采集页未保存的勾选不会生效。

应用、媒体、设备系统和 WhatPulse 配置按类别展开；WhatPulse 的开关、端口与错误在同组，歌词目录与索引诊断在媒体组。临时状态只在概览出现。账号服务地址与登录仅在设置出现，分享页未登录时提供前往设置的导航，不再弹出另一个窗口。

AccountWorkspace 在主窗口生命周期内只创建一次，持有两个原生内容控件和共享会话／授权草稿。顶层切页只改变可见性，不重新请求授权快照、不重建字段、不重置滚动、不创建新的同步订阅。公开和群编辑使用同一账号快照及 revision；刷新服务器状态或保存另一个受众时，保留其他受众的草稿及其原始 revision，不把旧草稿自动套用新版本。重新读取某个范围需明确确认丢弃该范围草稿；冲突时也保留当前选择。

CollectionOptions 明确限定采集页可写字段，不包含 Enabled、账号凭据、临时状态、开机启动或受众权限。保存采集会重配采集源并应用新的选择，但不会取消用户的 15 分钟暂停计时。只有显式开始／暂停／断开／退出改变同步意图。临时状态保存也不会开启暂停的同步。

已经开启开机启动的用户从新目录运行时，启动路径会更新到当前程序；没有开启者不会因这次布局更新被启用。退出账号管理和设备同步连接分开说明：已有设备但管理会话未登录时，可直接登录原账号管理分享，不需要断开设备。正在执行账号请求时阻止断开或关闭；未保存恢复码的关闭／退出提示保留。

验证使用 `dotnet build tests/windows -c Release --artifacts-path dist/windows-016-test`，然后显式运行输出目录中的 WindowsTests.dll，避免 dotnet run 的旧输出路径。行为测试包括暂停时保存不启动、运行时保存不暂停、采集编辑不覆盖账号／设备凭据／临时状态／启动设置。视觉验收应另外检查窄窗口滚动、长字段列表、深浅主题、切页草稿和真实设备连接；编译成功不代表这些体验已经验收。
