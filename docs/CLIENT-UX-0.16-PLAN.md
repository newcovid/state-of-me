# 0.16 客户端信息架构与界面计划

本轮只重组 Android / Windows 客户端界面与操作职责，继续使用 0.15 账号和字段授权协议。后端、博客和机器人接口保持当前版本。

## 一级页面

| 页面 | 回答的问题 | 内容 |
| --- | --- | --- |
| 概览 | 现在是什么状态 | 运行控制、真实同步结果、当前活动与媒体、使用统计；Windows 临时状态 |
| 采集 | 本机读取和上传什么 | 应用名单；播放器与歌词目录；设备信息；统计来源和同步；相邻的系统权限 |
| 分享 | 哪些人能看见什么 | 公开访客；QQ群身份验证与字段范围；真实公开预览 |
| 设置 | 怎样管理账号和程序 | 服务、注册/登录/恢复、设备、退出管理、断开本机、启动与后台 |

同步表示上传自己的账号；分享表示向公开访客或群提供访问。保存采集设置不应恢复已经暂停的同步。系统授权、本机采集、受众字段互不替代。

## 视觉与交互方向

Android 复用 Miuix 底部导航、紧凑标题、偏好行和对话框。Windows 复用 WPF UI 左侧导航、系统主题及单内容区，账号管理嵌入主窗口，取消综合账号弹窗。两端使用系统字体并尊重字号缩放。视觉重点是范围和授权状态，不引入装饰性图表或重复大卡片。

Android 参考色：页面 #F7F7F7、内容 #FFFFFF、正文 #171717、次要 #707070、操作 #3482FF、异常 #C83B3B。Windows 参考色：页面 #F3F3F3、内容 #FFFFFF、正文 #1A1A1A、深色背景 #202020、深色内容 #2B2B2B、操作 #0078D4。实现映射组件库语义色与系统强调色，深浅主题使用库支持。

正文左对齐；Android页边距16dp，Windows24px。普通条目按任务分组，不逐项套卡。概览中实时与统计使用轻量分段；分享与设置不再各嵌套一套综合导航。高级诊断默认折叠。权限已授予时展示状态而非持续要求授权。

## 状态与流程约束

- 页面切换保留各自滚动位置、输入、未保存范围草稿和登记请求。
- 账号和分享页面共用会话及状态；不会因导航重复请求、启动采集或订阅系统事件。
- 公开与QQ群权限仍由服务端精确投影，版本冲突保留草稿。
- 恢复码未保存、账号失效、设备失效分别处理；退出管理不停止设备同步。
- 采集开关每项只出现一处。统计结果页不重复同步开关，音乐目录与播放器同区。

## 审查与验收

第一轮独立信息架构审查已完成，确认四页职责及同步/分享词汇。实现后由同一独立代理检查代码和完整操作路径，再结合实际截图复核。

重点路径：首次连接与系统权限；单页完成音乐/歌词设置；暂停后修改黑名单不恢复同步；只公开正在播放的歌曲；只允许某群查询手机统计；设备撤销后重新连接。

Android检查360dp、大字体、深浅主题与输入法；Windows检查最小窗口、缩放、键盘导航及嵌入账号页。自动化验证不代替实际界面验收；真实账号登录和授权修改留给用户输入凭据并选择范围。

## 实施结果

四页布局已完成。经过三轮独立审查，修复跨受众刷新丢草稿、恢复流程沿用旧窗口路径、未保存目录刷新旧索引、未保存恢复码断开丢失、Android旋转丢过滤名单等问题。Windows状态测试与构建通过；Android Release与lint通过，并已安装真机。

Android真机验证四页、输入法、130%字号及选择器操作可达，字号已恢复原值。Windows副屏概览已看到实际布局，其余点按与缩放按用户要求延期；没有将代码审查视为完整视觉验收。最终体验包另含最后审查修正，已运行的Windows初始预览需退出后启动最终包。
