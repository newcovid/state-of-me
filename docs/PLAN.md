# 0.1 最小闭环

目标：免 Root Android 音乐/应用与 Windows 前台应用，经过本地白名单过滤，写入独立服务；网页和 AstrBot 使用只读凭据查询。明确区分播放、暂停、暂无状态，45 秒失联过期。

交付顺序：
1. 独立 API、SQLite 当前快照、权限隔离、过期与防乱序测试。
2. 原生 Android APK：通知访问/MediaSession、可选 UsageStats、常驻采集通知、允许列表、暂停清空、本地 LRC。
3. Windows WPF：前台进程允许列表、锁屏/空闲隐藏、暂停清空。
4. 网页状态页、AstrBot 只读工具、部署与安装包。
5. 真实设备安装和通路检查；用户进行音乐、权限、省电和隐私体验验收。

首版不要求 Root、LSPosed 或词幕。Lyricon 是未来可选增强；Android 标准 MediaSession 不保证提供歌词，使用用户主动选择的 LRC，按标题绑定，换曲立即失效。无歌词直接显示未提供。没有默认云端歌词查询或音频采集。

首版无历史数据库、无后台自动开机采集、无公开默认分享。未来扩展 SSE、设备配对/管理、权限预览 UI、Lyricon、更多平台与正式签名发布。0.1 为开发预览，不宣称长时省电或应用商店发布验收。

## 通用性约束与后续顺序

新增能力先定义平台无关的数据语义、权限和失效边界，再实现具体采集或机器人适配。个人 QQ、群号、域名、播放器偏好仅存在部署配置，不进入核心规则。

- 已完成：歌词窗口计算从 Android Service 分离为纯 Java 模块，独立验证高密度裁剪、前后跳转、前奏、歌曲结束与空歌词。
- 下一阶段：播放事件触发更新与心跳分离，合并突发事件并遵守服务端限流，保留不同播放器的标准 MediaSession 路线。
- 后续：设备配对和凭据管理、身份适配接口、多播放器和 ROM 验证；多用户支持需要独立的用户与设备授权模型。
