# Android 使用统计 0.14

## 开发与验收计划

1. 独立的本地统计引擎：增量处理系统使用事件，按设备时区跨日分桶，保留最近 30 天；首轮尝试回补最近 7 天，标记覆盖范围，未知不填成零。
2. miuix 统计页：今日屏幕交互／解锁使用时长、解锁次数、应用排行榜、7／30 天趋势；权限状态、刷新、清除记录与单独分享开关。
3. 独立历史接口：设备凭据写入汇总，账号本人查询；群授权独立开启，不加入博客公开范围。应用明细沿用本机应用过滤。
4. AstrBot 使用独立历史工具，保留真实发送者／群主身份解析。解释统计时间范围与覆盖缺口，不把历史当成实时活动。
5. 验证跨日、暂停、锁屏、多 Activity、时区、重复同步、租户隔离、撤权和离线历史；构建、安装到手机并验证权限与真实数据。
6. 发布 Android APK 与当前 Windows ZIP，附 SHA256、版本差异和从零连接说明。

## 口径与交互

- 使用现有 miuix 主题、字体和 Card / TabRow / Preference；不另造组件皮肤。统计页按“时间范围 → 屏幕统计 → 趋势 → 应用排行 → 分享与清除”排列，左对齐。颜色跟随 miuix 系统深浅主题，仅趋势条使用主题主色。
- 屏幕交互时长来自 SCREEN_INTERACTIVE / NON_INTERACTIVE，不等于注视时长。解锁使用是交互中且 KEYGUARD_HIDDEN 的区间；解锁次数为已知锁定到解除的转换次数。
- 应用前台区间按包聚合，重叠 Activity 不重复计时；屏幕关闭或锁定时不累计。应用合计与屏幕时长不能互相替代。
- 本地保留全量包级统计，上传应用明细前使用分享过滤；屏幕总量独立于应用过滤，不可据此推导被过滤应用。
- 明细只上传每日前 50 个允许的应用并明确截断标记，不上传事件轨迹。统计记录和实时状态 TTL 分开，15 分钟择机同步，网络故障退避；停止分享时撤下服务端历史，保留本地记录。
- 事件保留期由系统决定，首日和缺失区间标为不完整；首次启动前的全部 30 天不能保证回补。时区变化重建本地窗口，避免把不同日界混算。
- 无 root、无无障碍服务、无全局触摸或输入内容采集。现有实时分享授权不隐含历史统计授权。

## 使用方式

1. 手机打开“统计”，授予使用情况访问权限（已授权则直接显示 ✓）。首次打开会建立本地记录，并注册系统低频补算任务。后台任务可被系统省电策略延后；低电量时不强行唤醒。
2. 需要云端查询时开启“同步使用统计”，保持状态页已开始分享。点击“刷新统计”可立即重试；常规后台同步间隔至少 15 分钟。暂停分享会尝试清除云端统计，本地仍会补算；网络不可用时清除也会等待重试。
3. 账号页面展开“手机使用统计”即可查看自己的数据。要给群使用，在已授权群下点击“允许本群查询使用统计”。原有群授权默认不开启此项。
4. 群内可以询问“我今天用了多久手机”“我近七天主要在用哪些应用”。AstrBot 自主选择 `get_usage_history(days=1|7|30)`，身份校验与实时状态共用。
5. “清除统计记录”从当前时间重新累计，不会重新导入已清除历史。断开账号会同时清除本地记录、取消补算任务，并删除服务端设备记录。

## 接口与部署

- `POST /v1/usage`：设备 Bearer 凭据，完整替换该设备最近 30 天日汇总；`{"clear":true}` 清除。旧采样不能覆盖较新记录，重复同步不重复累加。单次上限 1 MiB，最多 30 天、每天 50 个应用。
- `GET /v1/accounts/usage?days=1|7|30`：本人账号 Cookie，离线设备的历史仍可查看，返回采样时间。
- `POST /v1/accounts/groups/usage`：本人账号与 CSRF 校验，`group_id` 与 `enabled`，只能更新已经绑定授权的群。
- `GET /v1/bot/usage/{qq}?group_id=…&days=…`：群机器人凭据及用户单独授权。返回每日总量和所选日期范围的前 50 项应用排行，缩小工具上下文。
- 统计没有公开接口，不注入博客组件。日汇总包含 `timezone`、`sampled_at`、`first_event_at`、`known_ms`。时长单位为毫秒；屏幕指标独立于应用过滤，不用被过滤应用的合计倒推屏幕时长。
- `known_ms` 是屏幕、锁屏两种状态均已知的覆盖时长，不保证厂商事件没有丢失。跨时区会重建本地统计窗口；中断超过一天时不把旧状态延长到未知区间。
- 数据按最近 30 个本地自然日读取；设备不再上传的整份旧记录在超过 30 天后的接口维护时清理。备份保留策略由部署者管理。
- 后端依赖 `tzdata`，避免新安装的精简容器没有 IANA 时区数据库。

若反向代理原先限制请求为 16 KB，必须单独允许统计上传。Caddy 子路径部署示例（放在同一站点内，通用状态路由之前）：

```caddyfile
handle /presence/v1/usage {
    request_body {
        max_size 1MB
    }
    uri strip_prefix /presence
    reverse_proxy state-of-me:8080
}
handle_path /presence/* {
    request_body {
        max_size 16KB
    }
    reverse_proxy state-of-me:8080
}
```

根路径部署则匹配 `/v1/usage`，无需 `strip_prefix`。Nginx 等代理也需要为这一接口设置相应限制。

## 验证记录

- Java 区间测试：跨午夜、重叠 Activity、关闭屏幕、重复旧事件、未知覆盖、夏令时重复小时、关机事件。
- Python：历史与实时分离、租户隔离、默认群拒绝、单独授权与撤权、重复替换、乱序、日期与时区校验、设备删除；适配器验证真实发送者及独立工具路径。
- Android Release 构建和 Lint 通过；一加实机读取屏幕、解锁和应用排行，已验证私有云同步及系统 JobScheduler 注册与执行。
- 仍需用户验证：与系统数字健康按相同口径对照、多天稳定性、省电限制下延迟和实际电量开销。短时实测不能作为长期耗电结论；不宣称与厂商统计完全一致。
