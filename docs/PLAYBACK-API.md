# 播放与歌词窗口协议（0.3）

现有 `/v1/events`、`/v1/status`、`/v1/public/status` 路径保持兼容。旧采集端可以继续只传当前句，新客户端应先升级服务端。

音乐对象新增可选字段：

- `track_id`：最多 128 字符的不透明歌曲标识。Android 使用播放器、曲目元数据及媒体 ID 的 SHA-256，不传文件路径。
- `playback_rate`：有限数值 0–8，默认 1；仅 `playing=true` 时推进。
- `lyric_window`：`{start_ms, end_ms, lines:[{at_ms,text}]}`，左闭右开，时间戳严格递增且位于窗口内。最多 16 行，每行最多 200 字符。没有同步歌词时为 null。

Android 在本机缓存解析后的时间轴，每次快照发送当前句及未来最多 60 秒的窗口；高密度歌词超过 16 行时，将结束边界缩短到下一条未传歌词。到达边界后消费者显示无缓存，不将末句无限续用。暂停、跳转、换曲在后续快照里重新提供位置和窗口。

服务端以接收时间为锚点推算读取时的 `position_ms`，随响应返回 `server_time`。这是近似实时位置，会受到上传/下载延迟影响；不依赖设备与浏览器墙钟完全一致。消费者以收到响应时的单调时钟继续推进，并在每次新快照时替换锚点，暂停时冻结、达到时长时停止、到 `expires_in` 时清空。不要叠加 `age_seconds` 再算一次位置。

## 权限与缓存

设备的 `lyrics=true` 允许上传和保留歌词窗口。读者必须同时拥有 `music`、`lyric`、`lyric_window` 字段权限才能看到窗口；只有 `lyric` 的机器人读者仍只得到服务端按窗口计算出的当前句。设备关闭歌词权限后，读取投影立即遮蔽歌词和窗口；页面在下一次轮询生效。

缓存仅存在采集端内存、服务端最新快照和当前网页内存中，不建立歌曲历史库，不使用 localStorage、Service Worker 或 HTTP 持久缓存。HTTP 仍为 `Cache-Control: no-store`，请求体上限仍为 16 KiB。断开、身份切换、请求失败或 TTL 到期清除页面缓存。

## 时效边界

当前采集端与网页均约 5 秒同步一次；网络正常时控制操作通常在约 0–10 秒加网络耗时内校准。缓存让歌词换句和进度条不再按轮询周期跳动，但不是毫秒级跨设备播放同步。旧客户端仅提供当前句时，网页可以平滑进度，不能预知下一句。无时间轴歌词不会伪造同步信息。
