# 播放与歌词窗口协议（0.3）

写入使用 `/v1/events`；账号读取使用 `/v1/accounts/status`，群读取使用 `/v1/bot/status/{qq}`，公开读取使用 `/v1/public/users/{name}`。歌词权限随账号的授权范围校验。

音乐对象新增可选字段：

- `track_id`：最多 128 字符的不透明歌曲标识。Android 使用播放器、曲目元数据及媒体 ID 的 SHA-256，不传文件路径。
- `playback_rate`：有限数值 0–8，默认 1；仅 `playing=true` 时推进。
- `lyric_window`：`{start_ms, end_ms, lines:[{at_ms,text}]}`，左闭右开，时间戳严格递增且位于窗口内。最多 16 行，每行最多 200 字符。没有同步歌词时为 null。

Android 在本机缓存解析后的时间轴，每次快照发送当前句及未来最多 60 秒的窗口；高密度歌词超过 16 行时，将结束边界缩短到下一条未传歌词。到达边界后消费者显示无缓存，不将末句无限续用。跳转、换曲在后续快照里重新提供位置和窗口。0.8.1 起暂停即撤下当前音乐，恢复播放后再提供新窗口。

服务端以接收时间为锚点推算读取时的 `position_ms`，随响应返回 `server_time`。这是近似实时位置，会受到上传/下载延迟影响；不依赖设备与浏览器墙钟完全一致。消费者以收到响应时的单调时钟继续推进，并在每次新快照时替换锚点，收到无音乐的快照时清空、达到时长时停止、到 `expires_in` 时清空。不要叠加 `age_seconds` 再算一次位置。

## 权限与缓存

设备的 `lyrics=true` 允许上传和保留歌词窗口。读者必须同时拥有 `music`、`lyric`、`lyric_window` 字段权限才能看到窗口；只有 `lyric` 的机器人读者仍只得到服务端按窗口计算出的当前句。设备关闭歌词权限后，读取投影立即遮蔽歌词和窗口；页面在下一次轮询生效。

缓存仅存在采集端内存、服务端最新快照和当前网页内存中，不建立歌曲历史库，不使用 localStorage、Service Worker 或 HTTP 持久缓存。HTTP 仍为 `Cache-Control: no-store`，请求体上限仍为 16 KiB。断开、身份切换、请求失败或 TTL 到期清除页面缓存。

## 时效边界

0.4 采集端通过标准 MediaController 回调触发更新，发送完成后至少间隔 1.1 秒，突发事件合并；同时保留 5 秒心跳。网页仍每 5 秒校准。回调有效时省去等待下一次采集心跳的时间；回调缺失或切换到尚未监听的会话时由心跳恢复。实际延迟还受请求耗时和系统调度影响。缓存让歌词换句和进度条不再按轮询周期跳动，但不是毫秒级跨设备播放同步。旧客户端仅提供当前句时，网页可以平滑进度，不能预知下一句。无时间轴歌词不会伪造同步信息。


## 0.8.1 当前活动语义

`music` 在状态读取接口中只代表正在播放。Android 保留媒体会话监听以接收恢复事件，但暂停/停止/缓冲/连接/错误时不发送歌曲；每次新快照替换旧快照。服务端写入和读取均过滤非播放音乐，因此旧客户端反复上传暂停歌曲、升级前已有的暂停快照也不会重新公开。

旧客户端只提供 `playing=true` 时兼容；明确的非播放 `playback_status` 优先于矛盾的 playing 标记。歌曲缺失不证明没有其他播放器或其他活动。暂停通知仍受设备回调、5 秒采样及网页 5 秒轮询影响，断网时按 TTL 失效，不是零延迟。

AstrBot 对一般近况问题只给模型主要活动信号（当前音乐、前台应用）；没有具体活动时可提供已确认的锁屏/充电状态。技术诊断字段只在具体问题中保留。提示词要求按当前工具结果回答，不沿用历史歌曲，不逐项播报未发生的活动，也不把缺失信号推断成睡觉、离线或什么也没干。信号筛选是代码行为；最终措辞仍由模型生成。

验证：29 项 Python 测试包含重复暂停心跳、恢复、旧快照撤回、矛盾播放状态、近况筛选与空结果措辞约束；JS 播放测试、Android 编译签名通过。未在群里发送测试消息，模型实际措辞需用户体验。
